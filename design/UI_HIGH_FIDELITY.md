# 雪约高保真 UI 规范

版本：V1  
日期：2026-11-23  
阶段：高保真设计评审

审阅图：[核心流程高保真稿](./screens/core-flow-hi-fi.png)

## 设计方向

以用户选定的浅蓝车头滑雪人 Logo 为视觉起点，界面采用克制的冰雪蓝、雪白、雾粉、香芋紫与少量荧光绿。整体保留年轻运动感，但不使用马卡龙装饰圆、连续渐变球或夸张营销口号。

核心识别关系：

1. Logo 是唯一强叙事图形。
2. 价格、时间、余位和路线始终优先于装饰。
3. 地图详情以真实道路地图为主视图。
4. 申请和审核在单屏内完成，不跳转到多个断开的页面。

| Token | 色值 | 用途 |

| Snow | `#F4F8FB` | 页面背景 |
| Paper | `#FFFFFF` | 卡片和底部抽屉 |

避免把粉色、紫色和荧光绿同时用于大块背景。高饱和色主要用于路线、价格、关键状态和单个主按钮。

## 字体与尺寸

- 中文正文：Noto Sans SC / PingFang SC。
- 数字：使用同一无衬线字体，价格和时间使用 600–700 字重。
- 页面标题：24–26px。
- 卡片标题：15–23px。
- 正文：9–12px。
- 辅助信息：7–9px；正式开发需结合系统缩放做可用性测试。
- 页面左右边距：18–20px。
- 卡片圆角：16–20px；底部抽屉顶部圆角 27px。
- 主要触控区：至少 44×44px。

## 页面一：找拼车

### 信息顺序

1. Logo 与消息入口。
2. 找拼车标题、日期和出发区域。
3. 起点、目的地和日期。
4. 查找空位按钮。
5. 拼车结果。

### 行程卡

- 第一行：车主头像、昵称、认证与同行次数。
- 第二行：出发时间和单人报价。
- 第三行：当前路线、途经点数量、预计到达时间、剩余座位。
- 第四行：可带雪具、吸烟规则和“查看路线”。

价格使用莓果色，余位使用香芋紫；其他信息保持深灰层级。

## 页面二：路线详情

- 地图占据首屏主要空间。
- 顶部提供返回、路线版本。
- 白色摘要卡显示日期、起终点、里程和预计时间。
- 底部抽屉显示价格、最低价、途经点、时间及申请入口。
- 精确集合点只有车主和已成交成员可见。
- 当前审阅图使用 OpenStreetMap 真实道路样例；开发阶段替换为高德地图 Android SDK。

## 页面三：申请与报价

### 字段

- 乘车人数。
- 雪具数量。
- 精确上车位置与新增绕行提示。
- 单人报价和自动计算的总价。
- 未成交不锁座说明。

### 操作

- 底部按钮文案包含最终总价：“提交申请 · ¥110”。
- 单价和总价同时展示，避免多人申请时产生歧义。
- 页面明确写出“线下结算”，不出现支付或平台担保文案。

## 页面四：车主审核

### 审核顺序

1. 申请人身份、人数、雪具和时间。
2. 当前路线与加入后路线的地图对照。
3. 新路线里程、增加时间和预计到达时间。
4. 乘客报价与最低价格。
5. 拒绝、回价、同意。

同意按钮显示最终总价，防止车主把单人报价误认为总价。

## 交互状态

### 申请

- 待审核：不占座。
- 已回价：不占座，建议 30 分钟内答复。
- 已成交：原子占用人数和雪具位，生成路线新版本。
- 席位冲突：明确说明失败原因，不自动占用其他行程。
- 放弃或过期：不改变路线与余位。

### 路线

- 计算中：保留地址列表，显示进度。
- 计算失败：允许重试，不掩盖错误。
- 无网络：展示缓存路线和更新时间。
- 路线发生变化：成员必须重新确认，旧版本可追溯。

## 可访问性

- 所有按钮必须有明确文本或可朗读标签。
- 不只用颜色表示状态，同时使用文字、时间和编号。
- 关键信息对比度满足正文可读要求。
- 动效只用于路线节点、成员加入和价格确认等状态变化。
- 系统开启减少动态效果后，取消非必要动画。
