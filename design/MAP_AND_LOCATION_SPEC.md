# 雪约地图与位置设计规范

版本：V1  
确认日期：2026-11-23

## 产品要求

乘客从拼车列表点入详情后，必须看到由地图服务计算的真实驾驶路线，而不是插画地图、静态示意图或无地理含义的装饰背景。

## 地图供应商

首发面向中国境内 Android 用户，建议接入**高德地图 Android SDK**。

选择原因：

- 中国道路和 POI 数据完整。
- 支持起点、终点、多个途经点的驾车路线规划。
- 支持路线里程、预计时长、地图交互和自定义 marker。
- 适合后续加入交通状态和导航跳转。

需要在开发前完成高德开放平台账号、Android Key、包名与 SHA1 签名绑定，并同步更新隐私政策和第三方 SDK 清单。

## 拼车详情页

### 地图主视图

- 起点：车主设置的出发位置。
- 途经点：所有已确认乘客的上车位置，按接人顺序编号。
- 终点：雪场入口或约定停车场。
- 路线：地图服务返回的真实驾驶路线。
- 摘要：总里程、预计时长、预计到达时间、路线版本和更新时间。
- 操作：缩放、平移、回到路线全览、展开全屏地图。

### 底部信息卡

- 日期与出发时间。
- 目的地、已确认人数、剩余座位。
- 当前最低价格。
- 起终点与途经点列表。
- 查看成员与申请加入。

### 隐私分级

| 浏览状态 | 地图显示 | 地址显示 |
| --- | --- | --- |
| 未登录 | 不显示路线 | 不显示 |
| 登录但未申请 | 真实路线可展示，精确接人点脱敏 | 只显示行政区域或商圈 |
| 已提交申请 | 真实路线与本人上车点 | 车主可查看申请人精确点 |
| 已成交 | 完整当前路线 | 同行成员可查看集合点 |
| 已完成 | 保留历史记录 | 按账号策略隐藏或删除 |

如果产品无法在脱敏状态下仍准确展示路线，应优先隐藏精确 marker，而不要展示可逆推出具体住址的信息。

## 车主审核页

必须提供两种地图状态：

1. **当前路线**：现有起点、已确认途经点和终点。
2. **加入后路线**：加入当前申请人的上车点后的新路线。

对照信息：

- 新增公里数。
- 增加分钟数。
- 预计到达时间变化。
- 修订后的接人顺序。
- 是否超过车主设置的最大绕行时间。

同意报价后，以新路线作为正式路线版本，并通知全部已成交成员。

## 地图视觉

- 使用浅色地图底图，降低非道路信息饱和度。
- 已走/当前路线使用莓果色 `#D85275`。
- 起点使用薄荷色，确认途经点使用香芋紫，终点使用莓果色。
- marker 必须带编号或文字标签，不能只靠颜色区分。
- 地图覆盖层使用白色高对比卡片，文字使用深靛 `#2D3049`。
- 不使用连续粉色渐变、发光路线或装饰性雪粒子遮挡道路。

## 状态与异常

- 计算中：显示骨架和“正在计算路线”。
- 计算失败：保留地址列表，提供“重新计算”。
- 无网络：展示最近缓存路线并标明更新时间，提供刷新。
- 路线超时：标记为旧路线，禁止把它描述为实时路况。
- 途经点顺序调整：重新计算成功后生成新版本。
- 地图服务不可用：至少展示文字路线、总里程和历史缓存，不显示空白底图。

## 测试要求

- 同一路线在常见 Android 分辨率下首屏可见起点与终点。
- 三个以上途经点不重叠，marker 可点击。
- 地图拖动、缩放、回到全览不导致底部卡片跳动。
- 前后路线切换后，距离、时长和 marker 同步更新。
- 无网络、弱网和地图 Key 错误时都有可理解的恢复路径。
- 精确位置只展示给有权限的用户。
